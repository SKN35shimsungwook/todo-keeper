# todo-keeper (할일 지킴이)

저는 기억력이 좋지 않아서, 프로젝트를 끝내지 않은 채 새 프로젝트를 시작하고 예전 것은 잊어버리는 일이 많았습니다. 그래서 Claude가 이걸 붙잡아 주는 스킬을 만들었습니다.

처음에는 "다른 주제로 넘어가려고 하면 세 번 말려 달라"고 하려 했습니다. 그런데 설계를 같이 점검해 보니, 저한테 필요한 건 막아 주는 게 아니라 **잊지 않게 다시 보여 주는 것**이었습니다. 그래서 흐름을 바꿨습니다. 낮에는 후보에 조용히 적어 두기만 하고, 다음 날 아침에 제가 직접 고르고, 손을 안 대면 그때 권하는 방식입니다.

## 만든 과정

- Claude 웹 검토와 Claude Code 검토를 나란히 놓고, 보수적으로 줄일 것과 남길 것을 정했습니다.
- "미완료"를 Claude가 판단하면 틀리기 쉬워서, 판단은 제가 아침에 하도록 했습니다.
- 스킬만으로는 새 대화가 이전 일을 모른다는 걸 알게 됐습니다. 그래서 SessionStart 훅을 붙였습니다.
- 매일 보고서를 따로 만들지 않고, 이미 쓰던 skill-scout 아침 디스코드 알림에 한 섹션으로 붙였습니다.
- 처음에는 제 스킬 묶음 저장소에 넣었는데, 계속 고쳐 가며 쓸 거고 훅과 시험 코드까지 있어서 저장소를 따로 뺐습니다.

## 배운 점

- 스킬, 훅, 예약 작업은 하는 일이 다릅니다. 스킬은 "어떻게", 훅은 "언제 자동으로", 예약 작업은 "정해진 시각에"를 맡습니다.
- 규칙은 날짜로 시험해야 믿을 수 있었습니다. 시험에서 "오늘 적은 후보가 오늘 바로 뜨는" 실수를 찾았습니다.

## 흐름

```
후보 ─(다음 날 아침에 고름)→ 진행중 / 아이디어 / 버림
후보 7일 동안 안 고름 → 아이디어함 자동 이동
진행중 ─(평일 3일 활동 없음)→ 멈춤 ─(하루 한 번 권유 ×3)→ 마지막 질문 ─(무응답)→ 보관
멈춤 중 활동 → 진행중 복귀
완료 ← 사용자가 직접 말할 때만
보관 30일 → 주간 점검에서 "버릴까요?" 한 번
주간 점검: 그 주 첫 대화 (보통 월요일)
```

활동으로 세는 것: 프로젝트 폴더의 git 커밋, 그 폴더에서 연 Claude 대화, "오늘 ○○ 했어"라는 말.

## 구성

| 파일 | 역할 |
|---|---|
| `SKILL.md` | Claude가 읽는 스킬 규칙 |
| `scripts/todo.py` | 상태 변경·날짜 계산 (토큰 0) |
| `install.py` | 스킬 폴더 연결(정션) + SessionStart 훅 등록 |
| `tests/test_todo.py` | 시나리오 시험 15개 |

데이터는 저장소 밖 `~/.claude/할일/projects.json`(원본)과 `진행중.md`(자동 생성 화면)에 있습니다.
skill-scout(`Desktop/skill-scout`)는 `todo.py brief`를 불러서 아침 알림에 붙입니다.

## 설치·시험

```bash
python -I -X utf8 install.py          # --check 로 상태만 확인
python -I -X utf8 tests/test_todo.py
```

## 명령

`python -I -X utf8 scripts/todo.py <명령>`: `candidate`, `choose`, `activity`, `complete`, `archive`, `restore`, `drop`, `edit`, `focus`, `morning-done`, `weekly-done`, `list`, `weekly`, `brief`, `hook-start`. 자세한 설명은 todo.py 맨 위에 있습니다.

규칙 숫자(평일 3일, 권유 3번, 후보 7일, 보관 30일)는 todo.py 상단 상수에서 바꿉니다.
